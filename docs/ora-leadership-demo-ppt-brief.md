## 第一部分｜当前 AI 困境（P03–P09）

### P03｜困境总览：天顶星科技，还在拼刺刀

- **核心句**：不是模型不够强，是协同方式、流程与工具仍在「拼刺刀」。
- **七个痛点簇**（本页做总览图，后页展开）：
  1. Agent 孤岛（协同断裂）
  2. 系统林立（学习成本）
  3. 流程鸿沟（水土不服）
  4. 「万国造」Skill/MCP
  5. Agent 工具负担
  6. 原始界面
  7. 工作方式落后（Worktree 缺位 → Token 跑不满）
- **视觉**：七宫格或环状痛点图；底部金句：「明明是天顶星科技，还在拼刺刀」

### P04｜困境：Agent 孤岛（上）—— 开发连贯性被强制打断

必须讲清三点：
1. **任务杂、场景多**：单一 Agent 难以覆盖；需要多种异构 Agent 协同。
2. **百花齐放却无法协同**：为做一个功能，开发者在多个 Agent 之间**来回拷贝数据** → **开发连贯性被强制打断**。
3. **共享靠污染**：多个 Agent 共用同一工作目录才能共享 → **极易目录污染**。
- **视觉**：开发者在 A/B/C 三个 Agent 窗口之间来回拖拽/复制的示意图

### P05｜困境：Agent 孤岛（下）—— 自闭症大脑 + 人被异化为手脚

必须讲清两点：
1. **上下文异构、记忆异构**：「你的记忆不是我的记忆，我的语言你一知半解」→ Agent 都是「自闭症」。
2. **有大脑、没手脚**：无法对接各系统、不会用合适工具 → 必须开发人员参与 → **人被异化为 Agent 的手脚** → 开发连贯性**再次被打断**。
- **收束**：孤岛的本质 = 无法协同 + 无法触达系统 + 人沦为胶水。
- **视觉**：左「异构记忆气泡互不相通」；右「人跪着给 Agent 递工具」的隐喻图（商务扁平风，勿低俗）

### P06｜困境：系统林立 + 流程鸿沟

**系统林立**
- 华为内部项目/开发/测试相关系统众多、逻辑复杂
- 开发者学习成本高，注意力被系统切换吞噬

**流程鸿沟**
- Spec 种类繁多，缺少适配**华为 IPD 流程**的 Spec
- 通用 AI 工具无法理解华为内部语境 → **水土不服**
- **收束**：Agent 进得了对话，进不了公司流程

### P07｜困境：「万国造」Skill/MCP + Agent 工具负担

**万国造 Skill/MCP**
- 管理标准不统一
- 本地 Skill/MCP 到处散落，缺少统一线上管理
- 知识难复用，质量无法保证

**Agent 工具负担**
- 「磨刀不误砍柴工，柴刀多了也误工」
- 多 Agent 并行时，**管理与配置本身成为负担**
- **收束**：能力越多，治理越乱，最后谁都不敢用

### P08｜困境：原始界面 —— 硬核不代表好用

- 各 Agent CLI 界面原始
- 信息密度不高、展示杂乱
- 信息获取效率低，直接阻碍开发效率
- **金句**：丢掉硬核的思想包袱 —— **Beauty does matter**（本页抛出，后文解答）
- **视觉**：杂乱 TUI 截意 vs 清晰 IDE 信息架构（示意对比即可）

### P09｜困境：工作方式落后 —— Token 再多也用不出去

- 随便找我司员工，能完整用过或说出 **Worktree** 概念的，不到一半
- 开发方式落后、工作习惯老旧；各 Agent CLI 仍在沿用这种落后方式
- **工作负载跑不满**：有并行潜力，却堵在一条命令行/一个目录里
- **金句**：明明是天顶星科技，还在拼刺刀
- **收束页过渡**：困境清楚了 → Ora 如何系统性解题

## 第二部分｜怎么解决（P10–P13）

### P10｜解题总纲：五招破局

| 2 | 自研 IPD 工作流 | 打通开发全链路，把人从系统中解放 |

### P11｜招式 1–2：三体世界 + IPD 工作流

**书同文车同轨**
- 统一协议与对象模型，让异构 Agent **共享上下文、记忆与产物**
- 不再靠「拷贝粘贴」或「污染同一目录」来协同
- **金句**：打造 Agent 的三体世界

**自研 IPD 工作流**
- 把华为开发语境与门禁写进工作流 / Spec / Skill
- 打通编码 → 测试 → 上库 → MR → 流水线 → 合入 → 回调
- **价值**：开发人员从繁杂系统切换中解放，从「Agent 的手脚」变回「决策者」

### P12｜招式 3–4：统一纳管 + Beauty

**统一本地管理规则 + Skill/MCP 市场**
- 本地有规则，云上有市场
- Skill/MCP 可导入项目统一纳管，也可选择后给 Agent 统一安装
- **金句**：本地云上一把抓；告别霰弹式修改

**Beauty does matter**
- IDE 级信息架构：高密度但不杂乱
- 桌面端 + Web 同源体验
- **金句**：丢掉硬核的思想包袱 —— 硬核不代表好用

### P13｜招式 5：把 Worktree 变成开发车道

- 任务自动分流到隔离 Worktree（像车道）
- 进度可视化管理，一目了然
- 多个 Agent **并排行驶**，不再堵在一条命令行里
- 创建 Worktree 像呼吸一样简单
- **金句**：欢迎加入并行世界 —— 让 Token 真正跑满负载

### P15｜Ora 核心能力（产品页）

用四块能力卡片（对应用户大纲第 3 点）：

1. **万物皆可插件化**  
   集成 Agent、IM、UI、Workbench、工作流；甚至把同事打包为插件。

2. **Agent 无缝切换，工具连续性最大化**  
   共享异构上下文、记忆与产物；一个应用完成所有操作，告别窗口间拷贝。

3. **并行世界**  
   呼吸一样创建 Worktree；以 Worktree 隔离任务；可视化进度；多 Agent 并发释放效率。

4. **统一纳管**  
   统一纳管本地 Agent 与配置；统一对接内部 Agent 市场；告别霰弹式修改。

### P16｜插件宇宙：类型与价值

| 插件类型 | 价值 | 举例 |
|----------|------|------|
| Agent | 对接异构大脑 | Claude Code、Codex、OpenCode |
| 工作流 | 打通 IPD/上库全链路 | 华为开发上库流程 |
| UI / Workbench | 提升信息获取与专业操作 | 可视化面板、评审台 |
| IM / 扩展 | 通知、协同、审批 | 即时通讯、回调 |
| 「同事」 | 人机协同也是插件 | 人工审批节点 |

- 小字技术点：TS + Bun；一插件一进程；进程可完整回收  
- **彩蛋金句**：你甚至可以把同事打包为插件

### P17｜领域对象：人不再当胶水

一句话模型：

```
Project
  └── Task  ──► Worktree（隔离车道）
        └── Session ──► Agent（可切换的执行器）
平台资产：Agent 定义 / Skill / MCP（Atoms + 市场）
```

- 人以 Project/Task 为中心，而不是以某个 CLI 为中心  
- **金句**：Agent 可以换，流程与资产留下

### P19｜场景① 故事说明（文字页）

安装对应 Agent 插件之后：
- 识别本地已安装 Agent  
- 识别其 Skill、MCP、配置等  
- **导入到项目目录统一纳管**  
- 或 **选择 Skill/MCP 给 Agent 统一安装**  
- 在 Ora 内选择插件 → 与本地 Agent 对话  

价值点：本地云上一把抓；配置不再霰弹式修改；知识可复用、可治理。

### P20｜场景① 流程图 ★必做★

节点与流向（必须按箭头顺序画）：

```
开始
  → 在 Ora 安装 Agent 插件（如 OpenCode / Claude Code）
  → 插件探测本地 Agent 安装与配置
  → 识别本地 Skill / MCP 列表
  → 分支：
        A. 导入到项目目录 → 项目内统一纳管（版本/启用/复用）
        B. 勾选 Skill/MCP → 向目标 Agent 统一安装/同步
  → 在 Atoms / 项目视图中确认纳管结果
  → 选择该 Agent 插件 → 创建 Task（自动 Worktree）→ 开启 Session 对话
结束
```

- **视觉**：流程图，分支用菱形「导入纳管 or 安装到 Agent」；两支汇合到「统一可见」再进对话。

### P21｜场景② 华为开发上库 —— 总流程图 ★必做★

标题建议：Skill 驱动的华为开发上库自动驾驶

**流程节点（顺序不可乱，失败必须回环）**：

1. 选择 OpenCode / Claude Code 插件  
2. 挂载「华为开发上库」Skill（及必要 MCP）  
3. Agent 编码实现需求  
4. 本地测试  
5. 提交代码到 **CodeHub**（华为内部代码托管）  
6. 创建 **MR**（类似 PR）  
7. 跑 MR 合并流水线  
8. **判断**：扫描是否通过？  
   - **否**（如格式问题）→ Agent 修改代码 → 重新提交 → **回到第 7 步**  
   - **是** → 继续  
9. 通知 Committer 合并代码  
10. 代码合并  
11. 消息回调 → 状态回写 Ora  

- **视觉要求**：整页流程图；主路径粗箭头；回环用橙色警告色箭头；CodeHub/MR/流水线节点可归入「企业系统」泳道色块。

### P22｜场景② 四泳道图（流向加强）

| 阶段 | 开发者 | Ora | Agent 插件 | CodeHub / 流水线 |
|------|--------|-----|------------|------------------|
| 准备 | 选择 Agent、确认 Skill | 加载工作流/纳管资产 | 就绪 | — |
| 开发 | 提需求、关键确认 | Task + Worktree 隔离 | 编码、本地测试 | — |
| 上库 | 可选审批 | 编排提交流程 | git push / 建 MR | CodeHub 收码、建 MR |
